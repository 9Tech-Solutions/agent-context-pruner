01 / THE APPROACH

Make room.
Keep the original.

Tool history builds up as an agent works. Pruner selects which calls and results to retain. The text it keeps stays word for word.

Read the architecture ↗
01

Pair and protect

Match each tool call to its result. Pin the first message and the newest messages so they stay in context.

02

Score what stays

A swappable scorer judges whether to retain each call and its full result. Use built-in rules or configure a model provider.

03

Keep, truncate, or drop

Your threshold decides the cut. Kept text is unchanged; truncated results keep a short head; dropped calls leave a note by default.

A dropped result may be needed later. Evaluate the tradeoff on your own sessions before choosing a threshold.

A FEW DETAILS

Before you try it.

More setup details and configuration options are in the documentation.

Does this rewrite retained text?

No. Kept content stays word for word. A result can also be truncated to a short head, or dropped with its call. Those actions are distinct from keeping it whole.

Do I need model API credits?

The heuristic scorer makes zero model requests. Network-backed scorers need their provider setup and may have usage costs. The browser playground needs neither an API key nor model credits.

Does the demo prove savings?

No. It explores a generated fixture and measures characters, with modeled full re-reads for lost results. It does not establish token, billing, subscription-usage, or real-task improvements.

Which agents are supported?

The published plugin targets Claude Code. The CLI evaluates saved Claude Code sessions offline. See the repository for current compatibility and setup requirements.
